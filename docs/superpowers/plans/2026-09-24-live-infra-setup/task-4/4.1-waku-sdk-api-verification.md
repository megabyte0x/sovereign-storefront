# Subtask 4.1: Verify `waku-peers.ts` against the installed `@waku/sdk` 0.0.36

Timebox: 45 min. Types and unit tests only, with one short live connectivity smoke at the end.

## Steps

1. Read `scripts/live-infra/waku-peers.ts` and `src/adapters/waku.ts`, which shows how this repo already creates light nodes. Match its imports and options.
2. For each API the script uses, find the real declaration under `node_modules/@waku/sdk`, `node_modules/@waku/interfaces`, `node_modules/@libp2p/interface` and `node_modules/libp2p`. Use `search_files` on `*.d.ts` and do not guess. Record the file:line for each:
   - `createLightNode` options (`defaultBootstrap`, `networkConfig`) and `waitForPeers` (its name and signature at this version: is it `node.waitForPeers([...])` or a standalone `waitForRemotePeer`?).
   - The `Protocols` enum member names (`LightPush`, `Filter`).
   - How to reach libp2p: `node.libp2p`, and whether `getConnections()` returns `Connection[]` with `remotePeer` and `remoteAddr`.
   - `peerStore.get(peerId)`: its return type, whether `protocols` is `string[]`, and whether `addresses` is `Address[]` with `.multiaddr`.
3. Refactor so that the address-building logic is a **pure** exported function, for example `export function dialableFromPeers(peers: { id: string; protocols: string[]; addrs: string[] }[]): string[]`. It keeps peers supporting both lightpush and filter (by protocol-string match, using the real protocol IDs found in step 2), appends `/p2p/<id>` when an address lacks it, and runs `browserDialable`. The live `main()` only collects `{id, protocols, addrs}` from libp2p, using the real API shapes.
4. Tests first in `tests/unit/live-infra-waku.test.ts`:
   - A peer with only lightpush is excluded. A peer with both, and one `wss` addr without `/p2p/`, gains the suffix and is kept. Duplicate peers dedupe. A `ws`-only peer is excluded.
5. Make `main()` type-check with no `any` on the SDK boundary. Use the real types.
6. **Live smoke (≤ 2 min, read-only):** run `node --experimental-strip-types scripts/live-infra/waku-peers.ts --dry-run`. Add a `--dry-run` flag that discovers, prints only the count per filter stage (connected, supporting both protocols, dialable), and writes nothing. Report those three counts.

## Verify
