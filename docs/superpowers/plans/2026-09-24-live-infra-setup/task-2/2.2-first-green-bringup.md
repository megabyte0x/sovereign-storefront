# Subtask 2.2: First clean `zcash-up.ts` run (exit 0) and doctor PASS

Timebox: 60 min, including builds. Precondition: Subtask 2.1 is done (scanner state lives under the short `SCANNER_DIR` from `scripts/live-infra/paths.ts`, and no old-path `serve` is running).

## Steps

1. Record the starting state in the report without printing secrets: `ths status --name ssf-live --json` (the `running` field only); `pgrep -af "sovereign-storefront-scanner serve"`; whether `SCANNER_JSON` exists.
2. Make `pollUntil` in `scripts/live-infra/zcash-up.ts` report *why* it timed out. Keep the last error message and append it to the timeout error: `... did not become ready within Nms (last: <message>)`. Today it swallows every error, which hid the ENOENT for hours. Truncate the message to 200 chars and never include response bodies. This is the only code change in this subtask unless step 3 exposes a new bug.
3. Run it with tracing, capturing output to a private diag file:

       mkdir -p -m 700 .runtime/live/diag
       ZCASH_UP_TRACE=1 node --experimental-strip-types scripts/live-infra/zcash-up.ts \
         > .runtime/live/diag/2.2-zcash-up.log 2>&1; echo "exit=$?"

   Expected: `exit=0`, and the log's last line is `zcash=up scanner=ready generation_advanced=true`. Also record from the trace timestamps the elapsed seconds between `step3: wallet sync ready` and `step6: scanner ready`. Subtask 2.3 needs that number.
4. If it fails, read only `grep -E 'trace|failed' .runtime/live/diag/2.2-zcash-up.log | tail -n 30`. Fix the cause if it is a clear bug in `zcash-up.ts`, using a failing unit test first when the logic is unit-testable. Then re-run. After 2 failed fix attempts, return `blocked` with the last error line and your hypothesis.
5. Doctor:

       npm run infra:doctor
       SSF_STRICT_LIVE=1 npm run infra:doctor; echo "exit=$?"

   Expected: `zcash PASS` and `scanner PASS`. The Logos and waku rows FAIL in strict mode because their `live.env` keys are missing. That is expected here, so the strict exit=1 is fine.
6. Confirm `live.env` has mode 0600 and contains exactly the keys `SSF_SCANNER_SOCKET`, `SSF_SCANNER_ACCOUNT_ID`, `SSF_SCANNER_SOURCE_ID` and `THS_ENV_NAME`, plus whatever keys existed before. Print key names only: `cut -d= -f1 .runtime/live/live.env`.
7. Leave everything running.

## Verify

- `npx vitest run tests/unit/live-infra-zcash.test.ts tests/unit/live-infra-paths.test.ts` passes, and `npm run typecheck` is clean.
