# Subtask 2.1: Move scanner state to a short path (fix the Unix-socket ENOENT)

Timebox: 60 min. Code change and unit tests, then one direct socket probe. No full bring-up. That is Subtask 2.2.

## Problem (already confirmed; do not re-investigate)

The scanner derives its socket path from the config file's directory: `<dir-of-scanner.json>/.<basename>.live-state/scanner.sock` (`services/scanner/src/config.rs:360-372`). With the config at `<worktree>/.runtime/live/scanner/scanner.json`, the path is 151 bytes. Linux `sockaddr_un.sun_path` holds at most 108 bytes. The Rust side binds through a short `/proc/self/fd/N/...` path, so the bind succeeds. Every client that connects by the absolute path gets `ENOENT`. Evidence: connecting by the absolute path gave ENOENT, and a relative connect from inside the directory returned `200 complete=true health=ready`. `src/adapters/wallet-scanner.ts:75` requires an absolute path, so a relative-path or chdir workaround is not acceptable.

## Change

1. In `scripts/live-infra/paths.ts`, add:
   - `export const SCANNER_DIR: string`. This is `process.env.SSF_LIVE_SCANNER_DIR` if set (it must be absolute), otherwise `path.join(process.env.XDG_STATE_HOME || path.join(os.homedir(), '.local/state'), 'ssf-live', 'scanner')`. On this host that is `/home/megabyte/.local/state/ssf-live/scanner`, and the socket path is about 82 bytes.
   - `export const SCANNER_JSON = path.join(SCANNER_DIR, 'scanner.json')` and `export const SCANNER_SOCKET = path.join(SCANNER_DIR, '.scanner.json.live-state', 'scanner.sock')`.
   - `export function assertSocketPathFits(p: string): void`. It throws `unix socket path too long (<n> bytes > 100)` when `Buffer.byteLength(p) > 100`, leaving margin under 108. It also throws if `p` is not absolute.
2. Create `tests/unit/live-infra-paths.test.ts` first (RED, then GREEN):
   - `assertSocketPathFits` accepts an 80-byte absolute path, rejects a 101-byte path with the message above, and rejects a relative path.
   - `SCANNER_SOCKET` passes `assertSocketPathFits`.
   - `SCANNER_DIR` honours an absolute `SSF_LIVE_SCANNER_DIR` and rejects a relative one. Test this through a pure helper `resolveScannerDir(env, home)` exported for testability, so there is no module-level env mutation.
3. `scripts/live-infra/zcash-up.ts`: replace the local `scannerDir`/`scannerJson`/`socketPath` derivation with `SCANNER_DIR`/`SCANNER_JSON`/`SCANNER_SOCKET`. Call `ensurePrivateDir` for `path.dirname(SCANNER_DIR)` (`ssf-live`) and `SCANNER_DIR`. Call `assertSocketPathFits(SCANNER_SOCKET)` before provisioning. The rest of the logic is unchanged.
4. `scripts/live-infra/zcash-down.ts`: use `SCANNER_DIR` for `serve.pid` and for `--reset` removal.
5. `scripts/live-infra/doctor.ts`: when `SSF_SCANNER_SOCKET` exceeds 100 bytes, report the scanner row as `FAIL` with the reason `socket path too long` in both strict and lenient modes. It is a configuration error, not an unreachable dependency. Add one unit test for this in `tests/unit/live-infra-doctor.test.ts`, exposed through a pure helper, for example `checkSocketPath(p)`.
6. Update `tests/unit/live-infra-zcash.test.ts` only if its expectations reference the old paths.
