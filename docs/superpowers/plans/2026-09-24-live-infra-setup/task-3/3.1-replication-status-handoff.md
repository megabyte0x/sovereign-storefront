# Subtask 3.1: Fix the replication-proof handoff between `logos-up.ts` and the doctor

Timebox: 45 min. Code and unit tests only. No live Logos run.

## Problem

- `scripts/live-infra/logos-up.ts` (around lines 321–330) writes `{ appImageSha256, peerIdA, peerIdB, replication: { cidPrefix, digestMatch, bytes } }` to `LIVE_ROOT/logos/status.json`.
- `scripts/live-infra/doctor.ts` `probeLogosReplication` (around lines 171–187) reads `LIVE_ROOT/status.json`. That is the doctor's own output, rewritten on every run. It also requires `replication.run === 'current'`, which nothing writes. The row can never PASS, and "current run" is not defined.

## Contract to implement

- A new file, `LIVE_ROOT/logos/replication.json` (0600), written atomically (tmp file, fsync, rename): `{ provedAt: ISO string, nodeAPeerIdPrefix, nodeBPeerIdPrefix, cidPrefix, bytes, digestMatch: boolean, daemonStartedAt: { a: string, b: string } }`. `daemonStartedAt` comes from whatever logosctl reports as its daemon start time or PID for each node. If logosctl exposes neither, use the daemon PID plus `/proc/<pid>/stat` start time. Choose one, document it in a code comment, and put it in `deviations`.
- "Current run" means the proof was made against the daemons that are running now: each node's current daemon identity (the same field as above) equals the recorded one, and each node's current peer-ID prefix equals the recorded prefix. If either daemon restarted since the proof, the row is SKIP (lenient) or FAIL (strict) with the reason `replication proof predates current daemons`.
- In the doctor, add a pure `export function replicationVerdict(proof: unknown, current: { a: {peerIdPrefix, startedAt}, b: {...} } | undefined, strict: boolean): Pick<Row,'status'|'reason'>`. Rules: a missing or malformed proof → `not yet proven this run`; `digestMatch !== true` → FAIL `digest mismatch` (in both modes); stale → as above; otherwise PASS.
- `logos-up.ts` writes `replication.json` and drops the `replication` field from its old `logos/status.json` (it keeps `appImageSha256` and the peer IDs there).

## Tests first (RED, then GREEN) in `tests/unit/live-infra-doctor.test.ts`

- A missing proof is SKIP when lenient and FAIL when strict.
- `digestMatch: false` is FAIL in both modes.
- A proof whose `startedAt.a` differs from the current one is SKIP or FAIL with the reason `replication proof predates current daemons`.
- A matching proof is PASS, and its evidence includes `cidPrefix` and `bytes` only.

If you extract the proof serializer as `replicationProof(...)`, add a test in `tests/unit/live-infra-logos.test.ts` that it rejects a full CID (only a prefix of 12 characters or fewer is allowed).

## Verify

`npx vitest run tests/unit/live-infra-doctor.test.ts tests/unit/live-infra-logos.test.ts` passes, and `npm run typecheck` is clean.
