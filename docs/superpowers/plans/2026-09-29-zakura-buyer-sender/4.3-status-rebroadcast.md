# 4.3 tx-status and rebroadcast  (parent Task 4.8–4.10)

Timebox 60 min. Owns: `tools/buyer-sender/src/pay.rs`, `tools/buyer-sender/src/main.rs`.

- `tx-status --attempt-id ID`: `read_attempt` (None → exit 2 `"no attempt recorded"`); connect; tip; `tx_status(txid, expiry, tip)`; print tx-status JSON (`minedHeight` null unless mined). Exit 0 on any definite state, 3 on `"transaction status unavailable"` (print `{"error":…}`).
- `rebroadcast --attempt-id ID`: read attempt (None → exit 2); connect; tip; `tip > expiry_height` → exit 2 `"attempt has expired; nothing was sent"`; else `broadcast(hex::decode(raw_hex))` and print `attempt_output(…)`, exit 0 on Accepted, 3 otherwise.
- Neither command needs the seed or a sync.
- Build with `RUSTFLAGS="-D warnings" cargo build --locked --release --manifest-path tools/buyer-sender/Cargo.toml` once, then `npm run build:buyer-sender`.

No tests.

Verify:
- Both builds exit 0, zero warnings.
- `tx-status --attempt-id <missing 64-hex>` against a probe state dir → exit 2 `no attempt recorded`.
- Read-only network probe: `tx-status` for a probe attempt whose txid is 64 zeros and expiry 1 → `state":"expired"` (NOT_FOUND + tip > 1) exit 0. If the server returns some other code for an unknown txid, record it verbatim (without the message) as evidence; do not change the NOT_FOUND rule — report it for the orchestrator.
