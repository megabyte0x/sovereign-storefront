# 4.1 Invoice validation (pure, pay.rs part 1)  (parent Task 4.2)

Timebox 60 min. Owns: `tools/buyer-sender/src/pay.rs` (new). Do not edit `main.rs` (3.1 owns it this wave); report `mod pay;` as a deviation.

Implement pure functions only (no I/O except reading the file in `read_uri_file`):
- `fn read_uri_file(path) -> Result<Vec<u8>, &'static str>`: owner = current uid, mode 0600, else `"invoice file permissions are unsafe"`.
- `struct Invoice { address: zcash_keys::address::Address, amount: Zatoshis, memo: Option<MemoBytes> }` (Debug must not print the address — implement Debug manually or omit it).
- `fn validate_invoice(bytes: &[u8], attempt_id: &str) -> Result<Invoice, &'static str>`:
  - `sha256(bytes)` hex (no trim, README C2) must equal `attempt_id`, else `"attempt id does not match the invoice"`.
  - UTF-8 → `zip321::TransactionRequest::from_uri`, else `"invoice is not a valid payment request"`.
  - exactly one payment, else `"invoice must contain exactly one payment"`.
  - recipient: `ZcashAddress::convert_if_network::<Address>(NetworkType::Test)`; must be a Unified address with an Orchard receiver, else `"invoice recipient is not a testnet unified address"`.
  - amount 1..=1_000_000 zat, else `"invoice amount is out of range"`.
  - memo: at most one (zip321 gives Option), pass through.
- `pub const FEE_RESERVE_ZAT: u64 = 100_000; pub const MAX_INVOICE_ZAT: u64 = 1_000_000;`

No tests (Wave 6), but keep everything callable from `#[cfg(test)]` with a fixture built from `UnifiedSpendingKey::from_seed(&ScannerParams::test_network(), …)`.

Verify: after the orchestrator adds `mod pay;`, `cargo check --locked --manifest-path tools/buyer-sender/Cargo.toml` exit 0 (unused warnings OK until 4.2).
