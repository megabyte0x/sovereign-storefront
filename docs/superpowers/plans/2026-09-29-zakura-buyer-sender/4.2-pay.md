# 4.2 pay: guard, propose, sign, persist, broadcast  (parent Task 4.1, 4.3–4.7)

Timebox 120 min. Owns: `tools/buyer-sender/src/pay.rs`, `tools/buyer-sender/src/main.rs`.

Read signatures only: `state.rs`, `chain.rs`, `pay.rs` (validate_invoice), and rc5 `propose_standard_transfer_to_address` (`zakura-client-backend-0.1.0-rc5/src/data_api/wallet.rs:1033`), `create_proposed_transactions` (same file, grep), `start_orchard_proving_key_warmup` (`lib.rs:94`, read its doc comment for the circuit-version argument).

`pay --uri-file F --attempt-id ID [--expiry-delta N]` in this order:
1. Guard (before any network or sync): `read_attempt(ID)` is Some → print the pay shape from the file with `"broadcast":"unknown"`, exit 4. The factory must not be called (6.1 will test with a panicking factory).
2. `read_uri_file` + `validate_invoice` → exit 2 on error. `parse_expiry_delta`.
3. Open wallet, account lookup, connect, sync (`SYNC_BUDGET`), summary; spendable < amount + FEE_RESERVE → exit 2 `"insufficient spendable balance"`.
4. Propose with `StandardFeeRule::Zip317`, `ConfirmationsPolicy::default()`, fallback `ShieldedPool::Orchard`, `None` for change memo/lock/version. Error → exit 2 `"payment proposal failed"`.
5. Warmup for the target height's circuit version; `LocalTxProver::bundled()`; `expiry = min_target_height + delta`; `SpendingKeys::from_unified_spending_key(usk)`; `create_proposed_transactions(..., OvkPolicy::Sender, &proposal, Some(expiry))`. Not exactly one txid → exit 2 `"proposal produced more than one transaction"`. Error → exit 2 `"transaction build failed"`.
6. `db.get_transaction(txid)` → `tx.write(&mut raw)`; `tx.expiry_height() == expiry` else exit 2 (README C4). `write_attempt` (created_at = unix seconds). **After this line every exit is 0 or 3.**
7. `broadcast(raw)`: print pay JSON; exit 0 on Accepted, 3 on Rejected/Unknown. If the attempt write succeeded but anything after it errors, print the pay shape with `unknown` and exit 3.

Also factor a `fn attempt_output(&Attempt, Broadcast) -> Value` used by guard, pay and (4.3) rebroadcast.

No tests. Do not run `pay` against a real invoice.

Verify:
- `npm run build:buyer-sender` exit 0.
- Probe guard: create `$TMPDIR/ssf-buyer-probe/attempts/<64 hex>.json` from a hand-written fake Attempt (0600) → `pay --uri-file /dev/null --attempt-id <that>` prints the recorded shape, exit 4, and does no network (run with `--lightwalletd https://127.0.0.1:1` to prove it). Remove the probe dir.
- `grep -nE 'raw_hex|to_uri|encode' tools/buyer-sender/src/main.rs` shows no raw tx or URI in any printed value.
