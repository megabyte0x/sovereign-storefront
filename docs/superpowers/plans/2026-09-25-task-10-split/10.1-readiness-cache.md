# Subtask 10.1: Per-product replica readiness cache (finishes slice-A fix round 1, Important #1)

Timebox: 60 min. Wave 1, serial. Precondition: none.

## Problem (from `task-10a-review.md`, Important #1)

- `src/runtime.ts` overrides only the `scanner` and `messaging` probes. `storageReplica` therefore falls back to the default in `src/seller/catalogue.ts:128-142`, which does a full Logos download of the *first* published product (up to 90 s).
- `GET /api/availability` in real-demo (`src/seller/server.ts` around line 445) calls `currentAvailability()`. So every page load triggers a download and reports the first product's state instead of per-product state. `catalogue.productAvailability` (lines 205-215) downloads again on every Waku `create`.
- `refreshReadiness` in `src/runtime.ts:250-266` downloads each product on every tick. All of these downloads serialize on the replica-dir lock in `storage.ts`.
- `stop()` awaits `readinessLoop.stop()`, which waits for an in-flight probe. A hung probe therefore blocks shutdown.

## Required behaviour

- Add `readinessTtlMs?: number` and `replicaProbeTimeoutMs?: number` to `RuntimeFactories`. Pick sane defaults, for example a TTL of 3× the readiness interval and a probe timeout of 30 s.
- Only the readiness loop (`refreshReadiness`) probes replicas. It writes a per-product cache entry `{ ok, checkedAt }`. Each probe is bounded by `replicaProbeTimeoutMs`; a timeout means `ok=false`. Probes stay non-overlapping.
- Request paths read the cache and never download. That covers `/api/availability?productVersion=`, `/api/availability` without a version, `catalogue.productAvailability` and Waku `create` issuance. An entry that is missing or older than the TTL means `storageReplica=false`. Under the stale-TTL test, the scanner also reports `false` when its cached readiness is stale.
- Wire this through the existing seam `startSeller({ replicaReady })` / `catalogue` `options.replicaReady`. Don't add a new global. `replicaReady(version)` returns the cached, TTL-checked value.
- `/api/availability` with no version must stop downloading the first product. Report from the cache: `true` if any published product's entry is fresh and ok. Or, if the test expects something else, follow the test.
- `stop()` must not wait for an in-flight replica probe. Use an `AbortController`, or stop awaiting the probe promise while the loop's timer is still cleared. After `stop()` resolves, no later probe result may write to the cache or the log.
