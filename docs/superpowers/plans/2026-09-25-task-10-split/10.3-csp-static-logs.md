# Subtask 10.3: CSP from configured peers, explicit dist/browser, log hygiene (Task 10 checkbox 5)

## Requirement (parent plan, Task 10 checkbox 5)

> Serve explicit `dist/browser`, no working-directory fallback in live mode. CSP uses the specific configured `wss:` peers (local `ws:` only for explicitly local setup), not `connect-src *`. Log only event class/status/timing and safe aggregate counters.

This subtask also covers slice-A review minor 3: `startSeller` accepts `mode: 'real-demo'` without a `live` block.

## Current code

- `src/seller/server.ts:32-42` has a static `CSP` constant with `connect-src 'self'`. The browser cannot reach Waku peers in live mode.
- `src/seller/server.ts:336-339` sets `publicDir` from `options.publicDir`, then falls back to `process.cwd()/dist/browser`, then to `process.cwd()`. The final fallback serves the working directory.
- `config.live.waku.bootstrapPeers` is a list of `wss` multiaddrs such as `/dns4/<host>/tcp/<port>/wss/p2p/<id>` (see `src/config.ts:230`).
- `src/ops/log.ts` is the operational logger.

## Required behaviour

1. In `server.ts`, export a pure `buildCsp(config)`.
   - Fixture mode keeps `connect-src 'self'`.
   - Real-demo sets `connect-src 'self'` plus one `wss://<host>:<port>` for each configured peer, parsed from the `dns4`, `dns6`, `ip4` or `ip6` multiaddr. It never emits `*` and never emits a bare `wss:`.
   - `ws://` is allowed only when the peer multiaddr is `/ws` (not `/wss`) **and** its host is loopback. Anything else is a ConfigError when `startSeller` starts.
2. In real-demo, `publicDir` must be explicit: `options.publicDir`, or `SSF_BROWSER_DIR` if you add it to config. Adding it would mean touching `config.ts`, which is owned by 10.6, so prefer the `options.publicDir` seam and note the gap under `deviations`. The directory must contain `index.html`, or startup fails. There is no `process.cwd()` fallback in real-demo. Fixture mode keeps its current behaviour.
3. `startSeller` must reject `mode: 'real-demo'` when `config.live` is absent. `tests/unit/security.test.ts` depends on the current behaviour (review minor 3). Update that test to pass a real-demo-shaped config with a `live` block, or have it assert the rejection. It is the only shared test file you may edit.
4. Log allow-list. `src/ops/log.ts` must drop or reject fields other than an allow-list: `event`, `component`, `status`, `ok`, `code`, `count`, `durationMs`, `generation` and `timing`. Only `code` and `count` take a string or number value. `code` must match `/^[A-Za-z][A-Za-z0-9_.-]{0,63}$/`, which rules out free-text messages. Check every current `logger.log({...})` call in `src/` with `grep -rn "logger.log(" src/`. If a call site uses a field you'd drop, extend the allow-list only when the field is a safe counter or enum, and list it.
