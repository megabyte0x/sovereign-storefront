## Current code (checked 2026-09-25)

- The admin server (`handleAdmin` in `src/seller/server.ts`, around line 547) checks `Authorization: Bearer <config.adminToken>` and serves **only** `GET /admin/health`. **There is no HTTP publish route today.**
- The "existing API" is the function `publishProduct(input: PublishInput)` in `src/seller/admin.ts:31`. It enforces the 41-byte plaintext limit (line 35), encrypts via `input.crypto`, publishes via `input.storage`, and runs `verifyReplica` (line 51). Its only caller is the fixture seed at `src/seller/server.ts:246-257`, which shows the exact arguments (dbPath, version, description, amountZat, network, plaintext, crypto, storage, replicaId).
- Publishing must run **inside** the seller process, because the crypto key store and the live storage adapter live there. A separate process opening the SQLite DB is not acceptable.

## Required behaviour

1. New module `src/seller/admin-publish.ts` exporting `createAdminPublishHandler(deps)`. `deps` holds `{ dbPath, network, crypto, storage, logger, maxBodyBytes }`. The handler has the shape `(req, res) => Promise<boolean>`, where `true` means it handled the request.
   - It handles `POST /admin/products` only. The caller has already checked authorization.
   - The body is JSON `{ version, description, amountZat, plaintextBase64 }`, capped at 4 KiB. It validates the version with the catalogue's version regex (look it up; don't invent a new one) and requires `amountZat` to be an integer string.
   - It calls `publishProduct` with `replicaId: 'replica'`. Success gives 201 `{ version, ciphertextCid, replica: true }`. `PayloadTooLarge` gives 413. A replica failure or an unavailable storage gives 503 `{ error: 'replica unavailable' }`. A duplicate version gives 409.
   - It logs only `{event:'admin.publish', ok, code}`. It never logs the plaintext, the description or the CID.
2. **Wiring into `server.ts` is NOT yours.** 10.3 owns `server.ts` in this wave. Under `deviations`, state the exact wiring change: in `handleAdmin`, after auth, `if (await adminPublish?.(req, res)) return;`, with `adminPublish` built from `core`'s crypto and storage. The orchestrator applies it after Wave 3, and 10.7 exercises it live. First find whether `core` exposes crypto and storage (`grep -n "crypto\|storage" src/seller/server.ts`), and state which fields to use.
3. `scripts/publish-live.ts` (run with `node --experimental-strip-types`). Usage: `--admin-url <url> --plaintext-file <path> --version <v> --amount-zat <int> --description <text>`.
   - Reads the token from `SSF_ADMIN_TOKEN_FILE`, which must be 0600. There's no token flag, and the token never appears in argv.
   - Reads the plaintext from a file and refuses anything over 41 bytes before sending.
   - Accepts only a loopback admin URL (`127.0.0.1`, `localhost` or `[::1]`).
   - POSTs to `/admin/products`. Prints only `published version=<v> cid=<first 12>… replica=ok`, or `publish failed: <status> <error>`.
   - No product fixture and no default plaintext.
