## Integration harness

Create `tests/integration/live-runtime.test.ts`. Put a separate `describe` that only runs when `SSF_LIVE_RUNTIME=1`. When that variable is set and a precondition is missing, the test **fails**; it never early-returns as a pass. It must:

1. Spawn `npm run start:live` (the path the user will actually use), or spawn `node dist/service/main.js` with the same env that `buildLiveEnv` from `scripts/start-live.ts` produces. Use a fresh `SSF_DB_PATH` under `.runtime/live/diag/10.7-<ts>/` (0700) and ports 0 or free fixed ports.
2. Parse stdout for the `public`/`admin`/`ready` lines, with a deadline of 60 s. The scanner cold start is about 2 s.
3. Check `GET /api/availability`: `scanner=true` and `messaging=true`. Before publishing, no product is ready.
4. Publish one product (41 bytes or less) with `scripts/publish-live.ts` against the admin URL. Then poll `/api/availability?productVersion=<v>` until `storageReplica=true`, with a deadline of 120 s.
5. `GET /api/product` returns the published version and a `sellerKeyId` equal to the persisted identity public key. Read it from the seller identity file the runtime created, using the existing identity reader in `src/seller/identity.ts`.
6. Disabled routes: real-demo `POST /api/checkout`, `/api/status` and `/api/recover` over HTTP return 404 (or whatever status the code sets for disabled routes; quote it).
7. The CSP header's `connect-src` contains the configured `wss://` hosts and no `*`.
8. Stop and restart: SIGTERM the child. It exits 0 within 10 s. The public and admin ports are free afterwards: a `net.connect` to each port fails. No child PID is still alive. Then start again on the **same** DB. The same `sellerKeyId` is reported, and the product is still published. SIGTERM again.
9. Leak check at the end: `ps -eo pid,args | grep 'dist/service/main.js' | grep -v grep | grep -v 'bash -c'` is empty (don't self-match with `pgrep -f`). The `ths`, Logos and scanner processes still run, since you didn't own them. Check this with `SSF_STRICT_LIVE=1 npm run infra:doctor` exiting 0 afterwards.

Run it with `SSF_LIVE_RUNTIME=1 npx vitest run --config vitest.integration.config.ts tests/integration/live-runtime.test.ts 2>&1 | tee .runtime/live/diag/10.7-run.log`, then read `${PIPESTATUS[0]}`.
