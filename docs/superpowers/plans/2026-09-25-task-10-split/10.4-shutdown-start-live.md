# Subtask 10.4: Signal shutdown, entrypoint and `npm run start:live` (Task 10 checkbox 6, part 1)

Timebox: 75 min. Wave 3, **parallel** with 10.3, 10.5 and 10.6. Precondition: 10.2 is clean.

## Requirement (parent plan, Task 10 checkbox 6)

> Add SIGINT/SIGTERM and partial-start shutdown for subscriptions, peer clients, timers, scanner adapter, servers and stores. Startup script prints URLs/ready states only; stops only resources it owns.

This subtask also covers slice-A review minor 8: the startup `refreshReadiness()` delays printing the URLs. After 10.1 it is bounded, but `main` should still print URLs first. Runbook and publish work are in 10.5.

## Current code

- `src/main.ts` (19 lines) calls `startRuntime`, awaits `refreshReadiness()`, then prints. It has no signal handling, and a startup error is an unhandled top-level rejection.
- `startRuntime(...).stop()` in `src/runtime.ts` is idempotent. It stops the loops, then the core, Waku and scanner. Partial-start unwind already exists inside `startRuntime`.
- `package.json` has no `start:live`. `live.env` has no `SSF_MODE` or `SSF_NETWORK`, so the script must supply `SSF_MODE=real-demo` and `SSF_NETWORK=regtest`.

## Required behaviour

1. `src/main.ts` exports `runMain(env, deps)` for tests. `deps` is test-local: `startRuntime`, a `process`-like signal emitter, `exit` and `stdout`. The module entry calls `runMain(process.env, realDeps)`.
   - On success it prints exactly three kinds of line: `public <url>`, `admin <url>`, and then `ready scanner=<bool> messaging=<bool> checkout=<bool> products=<n>`. The last line comes after the first readiness refresh. URLs print before readiness. It prints nothing else.
   - On the first SIGINT or SIGTERM it calls `runtime.stop()` once and exits with 0. A second signal during stop forces exit 130. Stop has a hard deadline (10 s by default); if the deadline passes, log `code=shutdown_timeout` and exit 1.
   - A startup failure prints one sanitized line `startup failed: <ErrorName>` with no message text (messages can contain paths), and exits 1. `startRuntime` has already unwound.
   - Fixture mode keeps its current behaviour, but also gets signal handling.
2. `scripts/start-live.ts` (run with `node --experimental-strip-types`):
   - Reads `.runtime/live/live.env` without printing it, and requires mode 0600.
   - Overlays `SSF_MODE=real-demo`, `SSF_NETWORK=regtest` and `SSF_ADAPTER_{MESSAGING,STORAGE,SCANNER}=real`.
   - Fills in the default paths listed in the index README under "Decisions already made", unless the caller's env already sets them:
     - `SSF_SCANNER_CONFIG` defaults to `SCANNER_JSON`, imported from `scripts/live-infra/paths.ts`.
     - `SSF_ADMIN_TOKEN_FILE` defaults to `.runtime/live/seller/admin.token`. If that file is missing, create it with 0600 permissions and 32 random bytes in hex. Never print it.
     - `SSF_DB_PATH` defaults to `.runtime/live/seller/seller.sqlite`, in a 0700 directory.
   - Checks that `dist/service/main.js` and `dist/browser/index.html` exist. If either is missing, prints `run npm run build first` and exits 2.
   - Spawns `node dist/service/main.js` with that env and inherits stdio, so only main's allowed lines appear. Forwards SIGINT and SIGTERM to the child and exits with the child's code.
   - Starts and stops only its own child. It never calls `infra:*`, `ths` or kill on other PIDs.
3. `package.json`: add `"start:live": "node --experimental-strip-types scripts/start-live.ts"`. This is the only `package.json` edit in the wave. Don't touch the lockfile.

## Tests (RED first)

- `runMain` with a fake `startRuntime` prints URL lines before the ready line. It prints nothing containing the token or a socket path.
- SIGTERM leads to `stop` being called exactly once and exit 0. A second SIGINT during a slow stop gives exit 130. A stop that never resolves gives exit 1 with `shutdown_timeout`, once a fake clock or short deadline has passed.
- `startRuntime` rejecting with an Error whose message contains `/run/secret.sock` prints `startup failed: Error` and never the message, and exits 1.
- `start-live`: export a pure `buildLiveEnv(liveEnvText, callerEnv)` and test it. It overlays the mode and network, rejects a live.env that isn't 0600 (via an injected stat), and never returns the admin-token contents. Test the missing-dist check with an injected `exists`.
