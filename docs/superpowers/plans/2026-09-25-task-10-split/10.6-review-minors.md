## Findings to fix (numbering from `task-10a-review.md`, "Minor")

1. `waku.ready()` latches to `true` after the first start, so the messaging probe never notices lost peers (`src/adapters/waku.ts` around line 168). Fix: have `ready()` reflect current connectivity, for example the connected-peer count from the node and whether the filter subscription is alive. Use only APIs the `WakuNode` type in `src/adapters/waku.ts` already exposes, or check `node_modules/@waku/interfaces/dist/waku.d.ts`. Don't invent SDK calls. Extend the test fake to control peer count.
2. Real-demo `loadConfig` returns `sellerKeyId: ''` when there is no pin (`src/config.ts` around line 316). Fix: make it `undefined` in real-demo, or assert that it is non-empty wherever it's consumed. The runtime overrides it with the persisted identity. Fix the type so an empty string can't be published.
4. Real-demo doesn't cap `SSF_MAX_HEALTH_AGE_MS` at 120000 or `SSF_MAX_CIPHERTEXT_BYTES`/`SSF_MAX_PLAINTEXT_BYTES` at 73/41. Fix: in real-demo, `ConfigError` on any value over those limits. **Also** update the composition test helper `liveConfig()` in `tests/unit/live-composition.test.ts:113-115`. It currently passes 1 MiB, so change it to 73 and 41. This is the one shared-test edit allowed, and only on those lines.
5. The `sent` and `sendInitiatedFor` arrays in the live messenger grow without bound (`src/adapters/live.ts`). Fix: remove them from the live messenger, or cap them (for example, a ring of 256). Add a test.
6. If `assertLiveAdapters` throws, the created adapters are never closed, and the Logos `mkdtemp` workDir leaks (`src/runtime.ts`, where `assertLiveAdapters` is called). Fix: close them best-effort, then rethrow. Add a test that a mismatched adapter's `close` or `stop` is called.
7. `readProtectedFile` checks the mode but not the owner uid (`src/config.ts` around lines 198-210). Fix: require `stat.uid === process.getuid()` where `getuid` exists. Add a test through an injected stat, or skip that test on platforms without `getuid`.

Findings 3 and 8 belong to 10.3 and 10.4. Finding 9 needs no code.
