## 5.1 Ebook demo site on Cloudflare Pages and automated public smoke (parallel with 5.3)

- **Owns:** `demo/ebook-shop/**` (new static site: `index.html`, `style.css`, `books.json`, no framework, no analytics), `demo/ebook-shop/wrangler.jsonc`, `tests/public/smoke.spec.ts` (new), `playwright.public.config.ts` (new). Timebox 2.5 h.
- **Site:** "Agent Mascot Books", a small random-ebook shop listing the two public-domain books published in 4.5. Each card has cover text, a blurb and `<ssf-buy product="<version>"></ssf-buy>`, plus the `embed.js` script tag with its SRI hash from `dist/browser/embed.sri.txt`. It listens for the `ssf:checkout` event and shows "Invoice opened" or "Delivered". Footer: "Zcash testnet demo. TAZ has no value."
- **Deploy:** `npx wrangler pages deploy demo/ebook-shop --project-name sovereign-store` (free on the existing Cloudflare account) → `https://sovereign-store.pages.dev`. If that project name is already taken globally, stop and ask. That origin goes into `SSF_EMBED_ORIGINS`.
- **Smoke specs** (`PUBLIC_ORIGIN`, `EMBED_ORIGIN` from env; missing env is a skip with a reason, never a PASS): (1) the catalogue on store. lists both books with the testnet badge and "3 confirmations"; (2) on the Pages site, clicking `ssf-buy` opens the popup `/p/<v>`, **Buy** yields a `zcash:utest1…` URI, the rendered QR decodes (jsqr) to the exact URI, and the Pages page receives `state:'invoiced'`; (3) ciphertext endpoint 200 with ETag and Range support; (4) security headers: CSP without wildcards, HSTS, `frame-ancestors 'none'` on app pages, `/admin/health` via the tunnel is 404; (5) served `index.html` bytes equal the build.
- **Verify:** `PUBLIC_ORIGIN=https://store.agentmascot.app EMBED_ORIGIN=https://sovereign-store.pages.dev npx playwright test -c playwright.public.config.ts` all pass. The smoke's unpaid invoices simply expire; check over SSH that the limiter was not hit.

## 5.2 T01: automated public-testnet purchase (real wallet, scanner and storage)

**Scope:** Complete the eight `PUBLIC_STAGE_IDS` from `scripts/live-report.ts` with two actual testnet payments. Playwright drives a persistent buyer browser; a new, **test-only local spending wallet** pays invoices. Neither CUA nor the regtest `scripts/live-pay.ts` can send public TAZ. The seller and its view-only scanner remain on the Pi. The user's existing wallet and the seller's spending seed are never read, imported, clicked or unlocked by this runner. CUA remains optional independent GUI coverage, reported separately; [index qualification](README.md#cua-scope-and-qualification-for-t01) still applies. No fixture adapter, faucet transfer to the buyer wallet, browser payment assertion or wallet "sent" message counts as a seller receipt.

Wallet state/evidence only under ignored `.runtime/public/` (0700 directories, 0600 files); never commit the Rust target or wallet data. Do not change production checkout, scanner policy or `scripts/live-pay.ts`.
- [ ] Pin and locally build/verify a CLI wallet with real public-testnet Orchard support. [Zingo CLI documents](https://github.com/zingolabs/zingolib/blob/master/zingo-cli/README.md) one-shot `--chain testnet --server https://testnet.zec.rocks:443 --data-dir <private-dir>`, `--waitsync`, `balance` and `send <address> <zatoshis> [memo]`; inspect the **pinned release's** `--version`, `help send`, output schema, network and recipient/memo behavior before writing the adapter. Do not assume the repo's `tools/payment-test-wallet` can spend: it only provisions a regtest UFVK. Build locally, never install globally or silently switch to mainnet.
- [ ] Create a fresh buyer wallet confined to `.runtime/public/buyer-wallet/`, not the user's U5 wallet. Pin its testnet chain/server and a maximum of two invoice amounts plus bounded network fees; reject any network other than `test`, non-`utest1`/unsupported receivers, expired invoices, extra ZIP-321 payments/fields, changed receiver/amount/memo, insufficient spendable balance and a third send. Use integer zatoshis. Never pass or print a seed; redact CLI stdout/stderr before evidence handling. An ambiguous send (timeout/crash after invocation) must be resolved using wallet history and scanner/chain txid before retrying, **never** blindly broadcast a second transaction.
- [ ] Fund this buyer wallet with enough spendable public TAZ for **two** invoices and fees. [The public testnet faucet](https://zcashfaucet.jinolabs.xyz/) currently advertises 0.1 TAZ per address/24 h and an in-browser proof-of-work puzzle; verify its live status and terms, respect its rate limit, and check whether that amount covers **both** selected prices plus fees. A faucet deposit funds the buyer wallet but cannot count as a T01 purchase. If unavailable or insufficient, the only human prerequisite is a one-time transfer from the user's wallet to the fresh testnet receiver, shown to them locally (never pasted into a report/chat). Confirm spendable balance and 3 confirmations before proceeding; if neither source works, mark 5.2a blocked with the actual reason. Do not unlock the user's wallet or bypass faucet limits to "automate" funding.
- [ ] Prepare `funds-received` with a **separate local view-only wallet** initialized from the seller's UFVK (not its seed), scanning public testnet from the seller birthday in its own state directory. Reuse the pinned scanner's viewing-only libraries if the CLI's UFVK import requires putting a key on the process command line. Never copy the UFVK into a CLI argument, log, browser or remote service. Preflight proves testnet identity and sync/catch-up without claiming a receipt; Task 5.2b marks the stage PASS only after this independent wallet actually sees the new invoice output/txid and amount. This checker cannot authorize seller release.
- [ ] Fix the public `live-observe init` preflight: obtain a **sanitized** running seller ready/component log and `dist/build-info.json` from the *deployed* Pi image/instance over the existing authorized Tailscale connection; compare the image/build digest and adapter versions to the actual running deployment. If required startup events have rotated away, capture a real seller restart during a no-payment maintenance window and recheck health; never compose a ready line by hand. The current default `.runtime/live/diag/manual-seller.log` and laptop AppImage hash are not evidence of the Pi instance. Add an explicit `--deployment-evidence <private-path>` for `--profile public init` containing real build info, image/module digests and sanitized running log; reject missing/mismatched values, fixture adapters and invented dirty-build provenance. Do not compare the evolving local T01 harness diff to an unchanged deployed app image. `init` must refuse to overwrite existing observations and is called only once by 5.2b `run` after preflight, not by 5.2a.
- [ ] RED tests: wrong-network or regtest URI refuses without invoking send; exact receiver/amount/memo binding; insufficient balance/third purchase refused; ambiguous send does not replay; missing or mismatched Pi log/build blocks `init`; sensitive CLI output is not recorded; invalid public `finalize` leaves no report. **Verify:** targeted unit tests and a harmless wallet `--version`/testnet sync/balance probe. **Done:** a funded, restricted buyer wallet; separately usable seller view-only checker; verified deployment-evidence inputs ready for the runner's `init`. No T01 PASS yet. **Blocked-exit:** no real TAZ, compatible sender/UFVK reader or deployed build evidence.

### 5.2b Build the fail-closed T01 runner (one worker, after 5.2a)

- **Owns:** `scripts/public-t01.ts` (new), `tests/unit/public-t01.test.ts` and `tests/public/t01.spec.ts` (new); recorder finalization tests in `tests/unit/live-observe.test.ts` belong to 5.2a and are coordinated before dispatch. The runner calls the existing recorder's `init`/`stage`/`finalize` path; no second report format and no source-text tests. **Produces:** `node --experimental-strip-types scripts/public-t01.ts preflight|run|status|finalize|verify-report`, with private resumable run state in `.runtime/public/`, one run lock and a fresh checkout per payment. `verify-report` reads the finished file, calls `validateLiveReport` and exits nonzero on any missing/invalid stage.
- [ ] `preflight`: require real public origin/embed origin, seller/scanner ready and caught up, replica available, testnet-only wallet with two spendable purchases, selected immutable product fixture hashes, actual Pi deployment provenance and an unused/private persistent Chromium profile. It **must not pay or call `init`** until these checks pass. `run` calls `live-observe --profile public init --deployment-evidence <private-path>` once, saves the run id, then drives `https://sovereign-store.pages.dev` → `<ssf-buy>` → popup `https://store.agentmascot.app/p/<version>` using Playwright. Do not reuse the six historical unpaid invoices.
- [ ] **Pre-payment recovery gate:** persist a new invoice, close the entire Chromium process and reopen the **same** dedicated profile; confirm the *same* order/credential and unchanged invoice is available in My purchases. Export the bearer-secret backup privately and successfully import it into a fresh isolated profile, checking the same seller/order. QR-decode the rendered payment request and compare it to that invoice's testnet receiver, exact zatoshi amount, optional memo and expiry. Only then invoke the wallet CLI to broadcast; no seed, URI, receiver or memo enters command logs or report evidence.
- [ ] After broadcast, bind the wallet txid to one scanner-observed canonical Orchard output **and the intended invoice**; poll a caught-up scanner until 3 confirmations, then inspect seller payment/delivery states and the buyer's authenticated package/ack. Reject a wallet success with no scanner match. Download/decrypt the harmless fixture through the browser; compare SHA-256 of **plaintext** with the original published fixture hash (not a ciphertext CID/ETag). Quit/relaunch the buyer browser again; recover from the same profile without sending again. Stage IDs: `embed-invoice`, `receipt-observed`, `three-confirmations`, `bytes-match`, `recover-without-repay`.
- [ ] For `restart-between`, issue a **second** fresh invoice and wallet transaction. After the scanner observes its output but **before** 3 confirmations, stop the Pi seller through the authorized Compose path; record the observed height/confirmation count, wait for the chain to reach 3, start the seller, then verify exactly one entitlement and authenticated delivery. If already at 3 before stop, the stage fails/needs a fresh distinct test payment; do not label a late stop PASS. For `origin-stop`, use the previously verified backup in a fresh profile; stop Pi `logos-a`, retrieve/decrypt through remote replica B and match plaintext digest, then restore A. Both service stop paths use `try/finally` to restart immediately on error or timeout, check health afterward and never touch the replica host's other services.
- [ ] `funds-received`: the independent local view-only seller-wallet checker (5.2a) syncs to the observed chain revision and finds the invoice output/amount; correlate with scanner/chain txid. Do not read or spend from the seller seed. Mark PASS only from that independent wallet view plus scanner evidence.
- [ ] Record each stage through `scripts/live-observe.ts --profile public stage <id> --status PASS|FAIL|NOT_RUN --evidence <sanitized summary>`. Map `PUBLIC_STAGE_IDS` exactly, with timestamps/txids kept only in ignored 0600 run state; a sanitizer rejection, missing proof or timeout must produce FAIL/NOT_RUN and a nonzero runner exit. On resume, inspect existing run state and wallet/scanner before acting; never call wallet send or `init` twice for one run. `finalize` passes the **actual** wallet name/version, lightwalletd URL, **first purchase's** transaction ID and chain confirmation count to `live-observe`; the second txid stays in private run state for `restart-between`. Validate all eight rows and `T01` **before** writing `.runtime/public/report.json` (fix the recorder's current write-before-validate order). Failed/incomplete runs retain private observations and an honest status, not a forged success report.
- [ ] RED tests cover profile loss before payment, QR/invoice mismatch, no scanner receipt, an ambiguous broadcast followed by resume, premature seller stop/restore, origin restore after download failure, two distinct purchases, plaintext mismatch and incomplete report refusing finalize. Run focused unit tests and a local no-payment Playwright dry run before live TAZ. **Done:** a runnable verified orchestration path, not mocked settlement. **Blocked-exit:** unresolved wallet sender or unavailable Pi/scanner/replica prevents payment and produces a diagnostic, never PASS.
